# Native TypeScript generation: definition of done

The user authorizes implementation of conversion from the authoritative Go type grammar to TypeScript, exposed by a CLI path option and an optional barrel export. Production generation remains native Go. This document supersedes the older research handoff where it selects concrete interfaces and output layout. The accepted `docs/spec/v1.md`, source registration rules, and validated `internal/typegrammar` define the source contract.

## Observable completion criteria

1. `gen-jsonschema [gen] --typescript <directory>` generates `types.ts` in the designated directory alongside ordinary generation. A relative output directory is relative to the invocation working directory; absolute paths work. The directory is created when needed. Omitting the option preserves existing generation. `--typescript-barrel` additionally generates `index.ts` with explicit type-only re-exports from `./types.js`; it is an error without a TypeScript directory. Every selected root and reachable named dependency has a stable, collision-safe exported type name. The module layout is intentionally one `types.ts` plus optional barrel.
2. A checked source/registration adapter constructs and validates the existing finite, acyclic Go grammar. It retains exact constants, JSON field selection/order/descriptions, numeric kinds, indirection, enum modes, named references, and each owner's field-local union registration. It diagnoses unsupported/custom/provider shapes and syntax-invalid compositions with source or field context. No permissive any/unknown fallback or inference of runtime codec semantics.
3. A native typed TypeScript expression/declaration representation and precedence-aware printer covers every admitted constructor. Scalars project to their wire primitives, time to string, enums to exact representable literals, objects to properties, Optional to absence, Nullable to required `| null`, pointers to their non-null values, and supported collections to arrays. Fixed Go array length is retained by the source grammar but does not introduce a stricter schema constraint in this structural TS projection. Named graph edges resolve to declarations. Field-local unions require exact discriminator literals, preserve singleton tags, narrow compatible existing payload discriminator properties without mutating shared payloads, and support direct I, Optional[I], and []I. Unrepresentable numeric literals fail rather than round or widen.
4. Strings, JSON keys, comments (including `*/`), Unicode, reserved names, and name collisions print valid TS deterministically. Empty object declarations exclude primitive/null values. The structural projection and a constructor-complete induction argument are recorded. The claim is structural typing, not JSON Schema validation equivalence, formal verification, or definitive bidirectional transport.
5. Generation renders and checks requested TS before writing it; unsafe output collisions do not overwrite user-owned files. Owned output can be regenerated. No-change checking detects missing or stale TS and barrel state even when schema output is unchanged, and does not modify the TS destination. Reruns produce byte-identical output. Disabling the barrel on a subsequent TS generation removes only a previously generator-owned index.ts, preserving unrelated destination files. Failure diagnostics name the output/path involved.
6. Meaningful Go tests exercise adapter admission/rejection, constructor composition, printing/escaping, exact literals, and CLI artifacts including custom/absolute paths, optional barrel, collisions, default behavior, determinism, and stale-output handling. Ordinary Go tests need no Node. A dedicated pinned TS compiler development/CI lane compiles actual CLI output with strict, exactOptionalPropertyTypes, and noUncheckedIndexedAccess. Consumer tests prove narrowing, exact tags, presence/nullability, enum membership, references, absence of any/unknown, complete switch acceptance, missing-case rejection, and a new variant breaking a formerly exhaustive handler. Bounded constructor-composition obligations have independently stated expectations.
7. Real consumer proof invokes the built CLI with Node unavailable on PATH, exercises the directory and barrel contract, verifies deterministic regeneration and stale TS failure, then compiles the actual generated output in the separate TS lane. `go test ./...` and appropriate lint pass after all implementation changes. Public usage guidance includes flags, output import example, type-only limits, and the separate runtime transport task. No new production Node/npm/JS-engine dependency is introduced.
8. Independent review under `/request-adversarial-review` and `/consensus` reviews the entire current implementation and proof against these authorities. All material findings are resolved and a retained round ends with `no findings` or `only nitpicks remain`.

## Internal seams and ownership

- Adapter: `func (s *SchemaBuilder) TypeDefinitions() (typegrammar.Definitions, error)` in new `internal/builder/typegrammar*.go`. Reuses scanner and registrations. Does not edit builder.go or CLI integration without coordination.
- Backend: package `internal/typescript`; `Generate(defs typegrammar.Definitions, options Options) ([]File, error)`, `Options{Barrel bool}`, `File{Name string; Content []byte}`. Produces basenames `types.ts` and optional `index.ts`. Export `GeneratedHeader` for artifact ownership detection. Owns only this package.
- CLI/artifacts: `BuilderArgs.TypeScriptDir string`, `BuilderArgs.TypeScriptBarrel bool`; flags and output management in builder/CLI. Renders once even when schema hashes are unchanged. Owns integration files and usage README.
- Coordinator: conformance lane, live consumer proof, induction evidence, worklog, integration and review adjudication. Full Go suites run serially because existing builder tests rewrite shared test_run fixtures.

## Review clarification

Exact enum membership and values must agree between the JSON Schema and TypeScript outputs of the same run. Constants belong by their resolved Go type, including conversion-typed constants; unrelated untyped constants do not become enum members. Arithmetic, conversions, escapes, and iota must resolve through Go's constant semantics rather than an AST spelling heuristic. This makes the existing exact-constant and shared-wire-contract criteria explicit following independent review round 01.
