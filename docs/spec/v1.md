# v1 Go/JSON contract

Status: accepted release contract, tracked by [#56](https://github.com/tylergannon/go-gen-jsonschema/issues/56). Implementation and conformance remain release prerequisites. This document specifies the 1.0 target; it does not claim that a release candidate already implements every row.

The product promise is a supported Go value crossing the JSON boundary without losing its defined meaning. Schema generation, JSON encoding, JSON decoding, and validation are separate capabilities. A generated schema alone is not evidence of a working codec. [#62](https://github.com/tylergannon/go-gen-jsonschema/issues/62) must demonstrate the complete supported matrix before release.

This contract supersedes the earlier draft's promises of blanket v0.5.3 compatibility, global enum adapters, scalar-only interface support, and post-v1 union/enum encoding. Current user guidance is in [llms.txt](../../llms.txt); #63 must reconcile that guidance with implemented release behavior.

## Supported boundary and semantic equality

For a supported Go value satisfying its declared field constraints, JSON encoding must produce a document accepted by its generated schema. Decoding that document must preserve:

- scalar values and enum values;
- absent versus present-zero Optional values, and null versus present Nullable values;
- the registered union implementation, including whether registration selected a value or pointer implementation;
- array/slice order and nested field meaning.

For accepted JSON input, decode/encode/decode must preserve the same meaning. Accepted input means schema validation **and** decoding into the declared Go type both succeed. JSON Schema can admit numbers outside a particular Go integer's range; Go decoding must reject those values rather than truncate or wrap. Schema validation is not a substitute for successful typed decoding.

Equality does not include JSON whitespace/property order, Go pointer identity or shared allocation, time monotonic readings/location identity, inactive wrapper payloads (`Present == false`), or YAML comments/style. `time.Time` equality uses the represented instant; finite float equality uses the Go value, not preservation of numeric spelling or the sign of zero. Invalid UTF-8 Go strings are outside the lossless domain. Arbitrary-precision JSON numbers and non-finite floats are not portable Go scalar values under this contract.

Ordinary fields remain required and non-null. A nil pointer or nil slice that encodes as null is not a valid non-null field value. Non-nil empty slices encode as `[]`. An `omitempty` or `omitzero` tag that removes a required ordinary property puts that value outside the valid domain; the tool must diagnose this limitation instead of claiming such tags express schema optionality. Use Optional for absence and supported Nullable shapes for null.

The matrix is deliberately not a Cartesian-product promise. ## Generated-method ownership

Registration is field-specific. Schema generation and both codec directions must consume one resolved field configuration, including enum mapping, union implementation set, discriminator property and wire value. A containing struct receives one composed `MarshalJSON` and one composed `UnmarshalJSON` when its fields require adapters. Separate union and enum implementations must not generate competing methods. Ordinary fields retain Go JSON tag, omission, nesting and custom-hook behavior within the declared supported domain.

Use a value receiver for generated `MarshalJSON` so encoding either a struct value or its pointer has the same field-aware behavior. Decode methods use pointer receivers. Do not add a global marshaler to a union implementation or enum type merely because one owner uses a particular wire representation. Reject production handwritten owner-method collisions before any output is written. Existing handwritten methods on concrete union implementations may be invoked as nested encoders only under the object/discriminator rules below; this does not authorize overriding owner methods.

For example, one `Created` implementation may be registered as `Impl("created", Created{})` under `type` in `Request.Event` and as `Impl("new", Created{})` under `!kind` in `Audit.Event`. The two owners must emit their respective discriminator. The Go implementation name cannot replace an explicit wire value.

Generated owner decoders decode into a fresh temporary value and assign only after complete success. Success replaces the receiver; errors leave it unchanged, including when a later slice element fails. This guarantee covers generated owner/wrapper code, not arbitrary user-hook side effects. Ordinary types using `encoding/json` without a generated owner retain its normal semantics; callers needing replacement use a fresh destination.

Validation and decoding remain separate entry points. Generated decoding is not a blanket substitute for required-field, unknown-field or enum-membership validation. Call validation first when accepting external documents under the schema contract.

## Union decisions for #57

- Support scalar `I`, `Optional[I]`, and direct `[]I` with the existing allowed registrations. Preserve selected pointer/value implementation types on decode. An unregistered dynamic type is an error even if it satisfies the interface.
- Explicit discriminator strings are the stable wire identity. Legacy derived names remain supported and use the bare implementation type name; renaming such a Go type changes that wire identity and requires consumer migration. Reject two legacy implementations with the same derived name before writing output; do not silently suffix one decoder name. Legacy and field-option paths must resolve each field through the same mapping. Decoder helper reuse must include discriminator configuration, not just the interface name.
- Concrete payloads must encode as JSON objects. Inject a missing discriminator. Preserve an already present discriminator only if its value is the registered string. Reject a conflicting/non-string discriminator, null or non-object payload; do not silently overwrite it.
- Reject nil interfaces and typed-nil implementations for required union values and slice elements. An absent Optional is omitted; a present Optional containing nil is an error. A nil `[]I` is not a valid required array and encoding must return an actionable error; an allocated empty slice emits `[]`.
- Single-implementation unions still carry the discriminator. Property names and discriminator values use JSON escaping.
- Duplicate discriminator registrations are errors. The three supported interface forms are a closed set, not examples of a broader family. Parenthesized/pointer forms and registrations reaching through inline/nested containers are excluded; register a supported named owner at the level where its union field is declared. Supported promoted fields must follow Go field-selection/shadowing rules, with explicit #62 evidence rather than assumed coverage. #62 must also cover mixed enum/union owners, supported nesting, custom object payloads and both pointer/value call sites.

### Concrete custom-hook boundaries

For an implementation registered as `Impl("created", Created{})` under discriminator `type`:

| Situation | Outcome and failure stage |
| --- | --- |
| Owner already has a production `MarshalJSON` or `UnmarshalJSON` that the generator needs to own | Generation-time collision error before any artifacts are written. A declaration stub in the mutually exclusive generation build is not a collision. |
| `Created.MarshalJSON` returns `{"name":"first"}` | Runtime encoding accepts the object and adds `"type":"created"`. |
| It returns `{"type":"created","name":"first"}` | Runtime encoding accepts and preserves the matching discriminator. |
| It returns `{"type":"deleted"}` or `{"type":3}` | Runtime encoding rejects the conflicting/non-string discriminator. |
| It returns a string, array, `null`, or malformed JSON | Runtime encoding returns an error; no object payload is emitted. Hook output is not generally decidable during generation. |
| `Created.UnmarshalJSON` rejects the object containing `"type":"created"` | Runtime decode returns that error without assigning the generated owner. Concrete hooks receive the complete discriminated object; the generator does not strip the discriminator to accommodate a hook. |

A nested ordinary custom hook that changes its schema's value kind is not made compatible by wrapping it in a generated owner. If incompatibility is evident from registration/method ownership, generation rejects it; otherwise its claimed support requires explicit schema/roundtrip evidence. The tool must report unproved arbitrary hook transformations as unknown, not infer validity by executing user hooks during inspection.

## Enum decisions for #58

Numeric mode uses underlying constant values. String mode uses registered constant names, never the output of `String()`. One Go type may appear in two owners or fields with different modes; each field follows its registration.

For string mode, unknown wire strings and underlying values without a registered name are errors, including an undeclared zero. Duplicate underlying values with different wire names are ambiguous for encoding: reject that string-mode registration before writing output, rather than choosing an unstable canonical name. Numeric/string-value modes may deduplicate identical enum values without changing their meaning. #58 must document any existing fixture affected by these restrictions and provide migration guidance.

Optional absence and Nullable null bypass enum value conversion; present values use the field's enum mapping. Handwritten owner-codec collisions are errors. Per-field enum adapters must not silently bypass incompatible nested custom hooks; unsupported combinations require an explicit generation diagnostic.

## Manual helper decisions for #59

`Strict == true` means all declared object properties are required and `additionalProperties` is false in both `JSONSchema` and `ObjectSchema`. It overrides explicit Required/AdditionalProperties settings; non-strict mode preserves them. Map-backed properties/derived required keys have sorted order; slice-backed object properties retain insertion order. Repeated encoding of the same schema is byte-stable.

`ConstSchema` and `EnumSchema` classify named integer/string values by their underlying kind. Legal JSON property names are escaped. `EnumSchema` retains its `SchemaNode` return signature; an empty enum returns a node whose `MarshalJSON` reports a descriptive error. It must not panic during construction or produce an invalid/permissive schema.

## YAML boundary

`--formats=both` adds canonical YAML input support using `go.yaml.in/yaml/v4`. Registered YAML decoding translates the YAML data model into JSON and uses the JSON path. JSON names and custom JSON hooks are authoritative; YAML field tags and nested custom `UnmarshalYAML` hooks do not redefine the contract. Use v4 scalar defaults to align decoding with validation. Known-fields decoder options do not replace schema validation inside generated hooks.

YAML decoding of registered types uses transactional replacement. Schema-backed validation must check unknown properties and required presence. YAML output, comments, anchors/alias identity, formatting and arbitrary YAML-specific Go values are not promised. Changes to the YAML dependency must preserve the documented canonical input behavior or receive an explicit compatibility decision.

## Provider API retained for 1.0

[#27](https://github.com/tylergannon/go-gen-jsonschema/issues/27) proposes replacing existing provider markers with a typed-props schema argument. The existing provider implementation is functional, not part of the disabled Tool/BuildTool experiment.

The maintainer approved retaining the current provider API for 1.0 on 2026-09-04. Preserve its schema-only/runtime-validation limits and defer an additive typed-props API beyond 1.0. The replacement/removal portion of #27 is superseded by this decision. Removing retained provider APIs after 1.0 requires a major release. #63 must preserve working provider behavior while removing the separate unfinished Tool/BuildTool experiment.

## Compatibility and release gates

Go 1.27+ and module mode are the current baseline. #66 must declare and test the supported platform/toolchain matrix before release; one machine does not establish universal portability.

Within 1.x, preserve supported exported Go APIs, registration meaning, generated method signatures/ownership, documented CLI flags, versioned machine-result fields, and the meaning of accepted wire values. Adding optional machine fields is allowed only where the result contract permits unknown fields. Removing supported fields/methods or changing established discriminator/enum representations requires a major release. Tightening rejection of inputs already outside the documented valid domain is a bug fix, not a new supported-input guarantee. The minimum Go version may increase in a minor release with an explicit release note and a tested support matrix; patch releases do not raise it. Dependency upgrades must preserve supported wire behavior, and changes to dependency types exposed in public signatures require compatibility review.

Generated source text, checksums and formatting are not an ABI. Their meaning and deterministic regeneration are contractual; upgrades may produce reviewed generated diffs. Provider/user hooks can be stateful, so deterministic output is promised only for the same deterministic inputs and hook results. A valid JSON Schema is not evidence of acceptance by every model provider's restricted schema dialect.

#60 publishes the installed binary's version/capabilities and structured diagnostic contract. #61 supplies read-only complete-artifact preview using the same rendering operations as generation. #63 removes unfinished product surfaces and stale claims. #64 packages the version-aware plugin. #65 proves real-agent workflows using artifact graders. #66 binds conformance, agent evidence and installation proof to the exact release candidate. App-server assistance, streaming helpers, arbitrary schema-to-Go generation and broader Go shapes remain outside 1.0.
