# polytype tutorial

This tutorial follows the current v1 contract. The authoritative capability
matrix is [`docs/spec/v1.md`](spec/v1.md); the compiling examples below show
the supported registration and generated-code paths.

## Quick start

Use a Go tool directive so the generator version is recorded in `go.mod`:

```bash
go get -tool github.com/tylergannon/polytype/polytype@latest
```

Add a generation directive beside the types, create a build-tagged
`schema.go`, and run:

```bash
go tool polytype new \
  -out schema.go \
  -methods 'Person=Schema' \
  --validate \
  --generate
go mod tidy
```

The generator writes a schema file and a `jsonschema_gen.go` file with the
requested schema accessor, validation method, and any selected codec
methods. Commit `schema.go`, `jsonschema_gen.go`, and the complete
`jsonschema/` directory.

Schema generation and codecs are separate. A schema describes accepted JSON;
`ValidateJSON` checks a document against it. Generated codecs exist only for
the documented supported shapes. Union codecs on the containing struct add
field-specific discriminators; concrete values marshaled alone use their
normal Go JSON encoding.

## Registration entry points

The normal entry point is a method marker:

```go
func (Person) Schema() json.RawMessage { panic("not implemented") }

var _ = polytype.NewJSONSchemaMethod(Person.Schema)
```

`NewJSONSchemaFunc[T](func(T) json.RawMessage, options...)` registers a free
function with the same receiver type. `NewJSONSchemaBuilder[T](func() json.RawMessage)`
registers a no-argument schema accessor stub and returns a `SchemaMarker`; the
generator emits the accessor (for example, `BuilderTypeSchema()`) that returns
the generated schema bytes. Both registrations are generation markers, not
runtime codecs. See the compiling entrypoint fixture under
`internal/builder/testfixtures/entrypoints` for all three forms.

## Optional and nullable fields

Use `Optional[T]` when a property may be absent and must not be null. Use
`Nullable[T]` when the property must be present but may contain null:

```go
type Person struct {
    Name  string                        `json:"name"`
    Email polytype.Optional[string]   `json:"email,omitzero"`
    Phone polytype.Nullable[string]   `json:"phone"`
}
```

`Optional[T]` is omitted from `required` and needs `json:",omitzero"`.
`Nullable[T]` remains required. Plain `json.Unmarshal` cannot distinguish a
missing Nullable property from explicit null, so validate first when that
distinction matters. The legacy `jsonschema:"optional"` tag is not honored.

The compiling runtime and negative-shape proof live in
[`examples/optionality`](../examples/optionality).

## Generate TypeScript declarations with the Go JSON boundary

Pin one explicit module release for both the generator and the imported
marker/runtime package. Generate validation and TypeScript declarations in the
same run:

```bash
go get -tool github.com/tylergannon/polytype/polytype@v1.0.0-rc.8
```

This combined surface requires `v1.0.0-rc.8` or newer: `v1.0.0-rc.4` includes
TypeScript declarations but predates generated owner codecs, and releases before
`v1.0.0-rc.7` predate the marker-based enum and sealed-union registration. Pin
the version explicitly.

```go
//go:generate go tool polytype --validate --typescript web/src/generated --typescript-barrel
```

The barrel flag is optional. Registrations such as `.Interface` and
`.StringerEnum` automatically generate the containing struct's JSON codecs;
there is no separate codec flag. Run `go generate ./...` and `go mod tidy`, then
commit the schema, Go, and requested TypeScript outputs together.

Use `json.Marshal` on the containing Go struct. Validate incoming JSON before
decoding it:

```go
if err := (Envelope{}).ValidateJSON(data); err != nil {
    return err
}
var value Envelope
if err := json.Unmarshal(data, &value); err != nil {
    return err
}
```

The TypeScript output contains structural declarations only. Consumers use
`JSON.parse` and `JSON.stringify`, but must supply their own runtime validation
for untrusted values because TypeScript annotations are erased. Generated
TypeScript runtime decoders and validators are not provided. The broader
executed Go/JavaScript transport proof remains tracked by
[#71](https://github.com/tylergannon/polytype/issues/71).

## Enums and interfaces

Declare an enum on the type itself with the marker method `func (T) enum() {}`
in ordinary Go; its same-package typed constants become the enum values
wherever the type is used. Use `.StringerEnum(field)` on a field of an integer
enum to emit constant names instead of integer values.

For a discriminated union, seal the interface with an unexported method and
declare that method directly on every variant. Membership is inferred; the
discriminator property is `type` and each value is the concrete type name:

```go
type Event interface{ isEvent() }

type Created struct{ Name string `json:"name"` }
func (Created) isEvent() {}  // value variant

type Deleted struct{ ID string `json:"id"` }
func (*Deleted) isEvent() {} // pointer variant

type Batch struct{ Events []Event `json:"events"` }

// schema.go (//go:build jsonschema)
var _ = polytype.Declare(Batch.Schema)
```

To discriminate on another property, declare it once in the package that
declares the interface: `var _ = polytype.SealedUnion[Event]("kind")`.

A reachable field of a non-sealed interface fails generation. A direct `[]I`
field becomes an array whose `items` contain the union. The generated owner
`MarshalJSON` emits the discriminator when called
through `json.Marshal(batch)` or `json.Marshal(&batch)`. Its decoder preserves
value versus pointer implementations and replaces the destination only after
successful decoding. An absent `Optional[I]` is omitted; nil required unions or
union slices are rejected during encoding. See
[`examples/sealed_interface_slices`](../examples/sealed_interface_slices).

## Providers and shared definitions

Provider options replace selected field schemas at runtime. The retained
provider forms are `WithFunction`, `WithStructAccessorMethod`, and
`WithStructFunctionMethod`; `WithRenderProviders` emits `RenderedSchema()`.
Provider-rendered types do not receive static validation methods because their
schemas depend on runtime values. See
[`examples/providers_rendering`](../examples/providers_rendering) and
[`docs/providers-documentation.md`](providers-documentation.md).

Use `AsRef()` on a type's own registration to put it in `$defs` and reference it
from other generated schemas. Without `AsRef()`, nested structs are inlined.
See [`examples/ref_types`](../examples/ref_types).

## Verification

For a repository using generated outputs, run:

```bash
JSONSCHEMA_NO_CHANGES=1 go generate ./...
test -z "$(git status --porcelain)"
go build ./...
go test ./...
```

The no-change check catches generated files that are untracked as well as
tracked schema changes. Use `--formats=both` when YAML input is required; YAML
is translated into the canonical JSON data model before validation and
decoding.
